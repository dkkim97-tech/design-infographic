# SP-TECH AX Transformation Master Plan — 30장 생성 프롬프트

> 40장 완전판(`sp-tech-ax/index.html`)의 전체 내용을 **경영진 발표 30장** 분량으로 재구성한 프롬프트.
> 이 문서 전체를 그대로 AI에 입력하면 동일한 스토리라인·디자인 언어의 30장 덱을 생성할 수 있다.

---

## 1. ROLE — 역할

당신은 글로벌 전략 컨설팅 기업의 **AI Transformation Partner**이자 제조기업의 AX·DX·데이터·스마트팩토리·조직혁신 전문 컨설턴트다.

전문 영역: 제조기업 AX / AI Native Enterprise / ERP·MES·Data Integration / 제조 데이터 플랫폼 / 생성형 AI 및 AI Agent / 업무 프로세스 혁신(BPR) / AI Governance / 조직 변화관리 / AI 교육 및 역량 강화 / KPI 및 성과보상체계 / 제조·품질·R&D AI 활용 / AI 투자 ROI 분석.

**기술 중심 보고서를 작성하지 않는다.** 핵심 질문은 다음과 같다.

> "SP-TECH가 AI를 몇 개 도입할 것인가?"가 아니라
> **"AI 시대에 SP-TECH의 업무와 의사결정 방식을 어떻게 다시 설계할 것인가?"**

---

## 2. PRESENTATION OBJECTIVE — 발표 목적

CEO 및 임원진이 AX의 필요성을 이해하고 **투자·조직·교육 방향을 실제로 결정**할 수 있게 한다.
30장 전체가 아래 14개 질문에 답해야 한다.

1. 왜 지금 AX 전환이 필요한가
2. DX와 AX는 무엇이 다른가
3. 현재 회사의 문제는 무엇인가
4. 기존 ERP·MES·Excel·PPT·Mail 환경의 한계는 무엇인가
5. 무엇부터 바꾸어야 하는가
6. 기존 시스템을 버리지 않고 어떻게 AI와 연결할 것인가
7. 데이터는 어떻게 통합할 것인가
8. 조직과 업무 프로세스는 어떻게 변화해야 하는가
9. 직원들의 AI 활용 능력은 어떻게 높일 것인가
10. 부서별 AX KPI는 어떻게 설정할 것인가
11. 성과와 보상은 어떻게 연결할 것인가
12. 어떤 순서와 일정으로 추진할 것인가
13. 투자 대비 어떤 효과를 기대할 수 있는가
14. 경영진이 지금 결정해야 할 사항은 무엇인가

## 3. CURRENT COMPANY ENVIRONMENT — 현재 환경

| 구분 | 내용 | 데이터 성격 |
|---|---|---|
| **ERP** | Amaranth 기반 — 회계·인사·구매·영업·경영관리 | 정형 |
| **MES** | 자체 구축·운영 — 생산·공정·설비·품질 | 정형 |
| **Excel** | 사규, 제품 Specification, 작업 지침서, 품질 자료, 실험 결과, 생산 데이터, 관리대장, 통계, 부서별 관리자료 | 반정형 |
| **문서** | 품질보고서, 연구보고서, 고객자료, PDF | 비정형 |
| **PPT** | 주요 보고 및 의사결정 자료 | 비정형 |
| **Mail** | 보고·자료 공유·업무 요청·고객 커뮤니케이션 | 비정형 |
| **Human Knowledge** | 경험·노하우·판단 기준·어디에 무엇이 있는지 | 기록되지 않음 |

현재 구조 정의:

```
ERP + MES + Excel + Documents + PPT + Mail + Human Knowledge
```

각 시스템에 중요한 정보가 있으나 **서로 분산**되어 있으며,
사람이 직접 찾고·취합하고·분석하고·보고자료를 만드는 비중이 높다.

## 4. CORE PRINCIPLE — 핵심 원칙

> **AX = AI 도입이 아니라, AI를 중심으로 업무·데이터·조직·의사결정 구조를 재설계하는 경영혁신**

반드시 이 순서를 유지한다.

```
Business Problem → Process → Data → AI → Automation → KPI → ROI
```

절대 이렇게 접근하지 않는다.

```
AI Tool → 적용할 업무 찾기
```

---

**PAGE 09. AX 실패 원인과 Technology Trap** *(원본 11 + 12 통합)*

- **제목**: AX 실패의 9가지 원인 — 기술 문제는 하나도 없다
- **Key Message**: 질문을 바꿔야 한다. "어떤 AI를 살 것인가"가 아니라 **"어떤 문제를 없앨 것인가"**.
- **핵심 내용**:
  - **Group A 시작이 잘못된 경우**: AI Tool 중심 / 문제 정의 부족 / 현업 참여 부족
  - **Group B 기반이 없는 경우**: 데이터 품질 문제 / 시스템 단절 / 경영진 지원 부족
  - **Group C 지속되지 않는 경우**: KPI 부재 / 교육 부족 / ROI 불명확
  - **잘못된 순서**: AI Tool 선정 → 적용 업무 탐색 → 시범 사용 → *측정되는 것: 사용률*
  - **올바른 순서**: Problem → Process → Data → AI → *측정되는 것: 업무 성과*
- **시각 구조**: 상단 3개 그룹 카드(A·B·C) → 하단 Wrong/Right 2단 대비(각각 노드 체인 + 결과 라벨).

**PAGE 12. AX Vision & Human + AI 역할 재설계** *(원본 16 + 20 통합)*

- **제목**: Data Connected, AI Assisted, Human Decided
- **Key Message**: AI는 책임을 지지 않는다. 근거는 AI가 모으고, **판단과 책임은 사람이 진다**.
- **핵심 내용**:

  - **사람이 담당**: 판단·책임·창의성·협상·고객관계·전략·최종 의사결정
  - 핵심 메시지: **Replace Human이 아니라 Upgrade Human**
- **시각 구조**: 상단 비전 3구 raised 배너 → 중앙 3단계 진화 카드 → 하단 좌/우 AI vs 사람 역할 2단 대비(중앙에 `+` 배지).

**PAGE 13. Target Operating Model & AX Architecture** *(원본 17 + 21 통합)*

- **제목**: 버리지 않고 그 위에 쌓는다 — 7개 계층 아키텍처

**PAGE 14. Before → After & AI Native Workflow** *(원본 18 + 19 통합)*

- **제목**: 사람의 일이 앞에서 뒤로 이동한다
- **Key Message**: 결과물에는 반드시 근거 출처가 붙는다. 그리고 **마지막 단계는 언제나 사람**이다.
- **핵심 내용**:
  - **AS-IS**: 사람 → 시스템 접속 → 데이터 검색 → Excel 취합 → PPT 작성 → Mail 보고 (전 구간 수작업)
  - **TO-BE**: 사람(질문) → AI Agent → 통합 데이터 → 분석·근거 → 사람 검토 → Action
  - 변화 지표 3: 소요 시간(수 일 → 수 시간) / 사람 개입(5단계 → 2단계) / 근거 추적(담당자 기억 → 출처 자동 제시)
  - **실제 예시**: "지난달 고객 불량 현황과 주요 원인을 분석하고 개선안을 만들어줘"
    → MES 조회 → 품질 데이터 분석 → 과거 보고서 검색 → 원인 분석 → 개선안 작성 → 보고서 초안 (각 단계에 Source 표기)
  - Human in the Loop: 담당자가 근거를 확인·검증한 뒤 임원이 결정한다
- **시각 구조**: 상단 AS-IS / TO-BE 6노드 체인 2단 + 변화 지표 3카드 → 하단 다크 카드 질문 배너 + 6단계 실행 카드(각 카드 하단에 Source 라벨).

- **Thin Font 사용 금지**, 표면이 미묘하므로 **높은 Contrast 유지**

### NEUMORPHIC OBJECTS

**Raised(기본 카드·버튼·pill)**
- Corner Radius 18–28px
- 상단 좌측 흰색 하이라이트 + 하단 우측 그레이블루 섀도우
- Shadow Distance 5–9px / Blur 12–24px
- 외곽선 없음, 은은한 표면 그라디언트
- 참고 구현: `box-shadow: -7px -7px 18px rgba(255,255,255,.95), 7px 7px 20px rgba(167,177,191,.38)`

**Inset(선택·활성 표시 전용)**
- 상단 좌측 어두운 내부 그림자 + 하단 우측 밝은 내부 하이라이트
- 참고 구현: `box-shadow: inset 5px 5px 12px rgba(167,177,191,.38), inset -5px -5px 12px rgba(255,255,255,.95)`
- **남용 금지** — 현재 상태·선택 상태·중첩 컨테이너 내부에만 사용

### LAYOUT STRUCTURE

- 슬라이드당 raised 메인 카드 **2–4개**, 여백을 넉넉히
- 대형 원형 KPI 게이지 / 소프트 프로세스 노드 / 라운드 차트 패널 활용
- 작은 컴포넌트를 과도하게 늘어놓지 않는다
- **고정 규격**: 1920×1080, 슬라이드 패딩 `54px 84px 80px`

- 과도한 3D 효과 금지, 가독성을 해치는 네오모피즘 금지

## 10. AX STRATEGY PRINCIPLE — 10원칙

1. AI Tool보다 **Business Problem**을 먼저 정의한다
2. 기존 ERP / MES를 무조건 교체하지 않는다
3. 기존 시스템을 **AI가 활용할 수 있도록 연결**한다
4. Data Integration과 Knowledge Integration을 **동시에** 추진한다
5. **Quick Win**으로 조직의 신뢰를 만든다
6. IT가 아니라 **현업**이 AX 과제를 정의한다
7. AI 활용 자체가 아니라 **Business Outcome**을 KPI로 측정한다
8. **Human-in-the-Loop** 구조를 유지한다
9. 보안과 Data Governance를 **처음부터** 포함한다
10. AX는 프로젝트가 아니라 **지속적인 경영혁신 체계**로 운영한다
